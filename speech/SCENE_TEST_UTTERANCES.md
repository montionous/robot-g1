# 四个语音场景的测试语句与头灯反馈

这份清单用于机器人主机恢复后逐项彩排。默认头灯是 `dry-run`，只打印灯光请求，不调用机器人脚本。只有同时传入下面两个参数时，才会调用主机上的 LED 脚本：

```bash
--robot-leds execute --confirm-g1-led-demo
```

手臂动作也独立保持同一安全边界；要执行已有动作执行器，还必须单独传入：

```bash
--robot-actions execute --confirm-g1-actions
```

两组参数彼此独立。只启用头灯不会启用手臂，只启用手臂也不会写入头灯。

脚本路径默认是项目根目录的 `scripts/g1_companion_led_test.sh`。若脚本仍只在队友的其他路径，可先用环境变量覆盖：`G1_LED_SCRIPT=/实际/脚本路径`。脚本不存在、超时或返回失败时，语音场景会继续运行。

当前主机脚本会在每次真实灯效前校验 SDK、配置并构建 LED 程序。`speech` 因此使用独立进程组执行它，默认最长等待 30 秒；超时或被新的灯光状态取代时，会清理脚本及其构建、管道子进程。若主机实测一次执行需要更久，在启动场景前设置 `G1_LED_COMMAND_TIMEOUT` 为略大于实测值的秒数。不要并行运行手动灯效命令和语音场景，它们共享同一个 `build/` 目录。

在首次启用真实头灯前，先确认主机上确实有这个队友维护的脚本：

```bash
test -f /home/user/github-product/g1-dex3-care-vla/scripts/g1_companion_led_test.sh
```

首次真机彩排前，先串行完成 SDK 预检和无硬件写入的构建预热：

```bash
(
  cd /home/user/github-product/g1-dex3-care-vla || exit 1
  time bash scripts/g1_companion_led_test.sh --check-sdk
  time bash scripts/g1_companion_led_test.sh --dry-run 25
)
```

`--dry-run 25` 不会写入 G1；它的 `real` 时间可用来判断是否需要提高 `G1_LED_COMMAND_TIMEOUT`。真实灯效的 JSON 记录由脚本保存到 `runs/companion-led/`。

当前 Git 仓库尚未包含该脚本；若检查失败，请由脚本所有者提交它，或设置 `G1_LED_SCRIPT` 指向已经验证过的实际路径。

| 交互边界 | 灯光编号 | 使用位置 |
| --- | ---: | --- |
| 正在倾听 | 25 | 开场、每次等待老人说话 |
| 正在处理 | 18 | 已接受有效需求后的意图、数据库或业务处理 |
| 等待确认 | 20 | 报名、联系人和拨号授权确认 |
| 已回应 | 19 | 成功播报、播放或安全桩请求已受理 |
| 请重试 | 14 | 未听清、识别失败或安全终止前提示 |
| 告别结束 | 22 | 结束、取消、超时或转场 |

业务流程不会自动使用强闪效果 24、色彩巡展 23、红灯或熄灯 0，避免对老人造成干扰。告别效果 22 后不会马上发 0，以免打断渐出。

| 场景 | 已接入的手势边界 |
| --- | --- |
| 护理咨询 | 首次有效护理回复时确认；老人主动结束或无响应结束时告别。 |
| 娱乐普通版、比赛版 | 原有开场问候、首次播放邀请、停止时告别保持不变。 |
| 社交普通版 | 推荐活动时邀请，选择或等待报名确认时确认，登记成功时庆祝，结束时告别。 |
| 社交比赛版 | 原有开场问候、推荐邀请和结束告别保持不变。 |
| 联系家人 | 识别到有效联系家人需求时确认；安全桩完成、取消或失败结束时告别。 |

动作请求采用现有执行器的串行保护：上一动作仍在执行时，后续动作会跳过；动作结果不作为语音、报名、护理或联系流程的前置条件。

## 1. 日常护理咨询

入口：`scenarios/care_consultation_support/run_g1_demo.sh`。同一入口加 `--showcase` 就是比赛展示模式；展示模式不写正式长期护理记忆和工作人员事项。

首次有效护理回复的自定义抬手起势较慢：动作执行器成功启动后，先留出 1.5 秒，
再播报这条护理回复。该提前量沿用娱乐场景的做法，只作用于本次会话的首次确认动作；
关闭、dry-run、忙碌或未成功启动动作时不增加等待，后续回复和官方挥手告别保持原时序。

| 顺序 | 测试语句 | 预期结果 |
| --- | --- | --- |
| 1 | `我今天膝盖有点酸。` | 进入护理咨询，低风险活动不适。 |
| 2 | `今天膝盖比平时明显加重，而且已经持续好几天了。` | 正常版产生工作人员关注事项；展示版只演示判断。 |
| 3 | `好的，那先这样吧。` | 主动结束咨询，头灯告别渐出。 |
| 单独测试 | `我一站起来就头晕。` | 识别头晕并进入需要进一步关注的护理分支。 |
| 单独测试 | `请帮我联系女儿。` | 验证转到联系家人需求；不要在这条链路继续发起拨号。 |
| 反例 | `今天天气不错。` | 不进入护理场景，提示可说哪里不舒服。 |

`我胸口很痛，喘不上气。` 会进入紧急协助转场；除非正在专门检查该分支，不建议在普通彩排中说这句话。

## 2. 娱乐陪伴

普通版入口：`scenarios/companion_entertainment/run_g1_demo.sh`。它默认陕西话交互，可用 `--dialect mandarin` 覆盖。普通版会依据共享需求库优先选择老人以前点过的内容。

| 顺序 | 测试语句 | 预期结果 |
| --- | --- | --- |
| 1 | `有点无聊。` | 询问想听哪类内容。 |
| 2 | `给我放点音乐。` | 播放音乐；第一次有效播放会触发现有展示动作和已回应灯效。 |
| 3 | `换一首。` | 切换下一首音乐。 |
| 4 | `我想听新闻。` | 切到新闻。 |
| 5 | `换成戏曲。` | 切到戏曲。 |
| 6 | `不听了。` | 停止播放、触发挥手告别和头灯渐出。 |
| 反例 | `这个新闻不错。`、`快一点。` | 不应被误当成控制指令。 |
| 反例 | `我想听甜蜜蜜。` | 走未找到内容的安全兜底。 |

比赛展示版入口：`scenarios/companion_entertainment/g1_showcase_demo.py`。它是固定顺序状态机：

1. `给我放点音乐。`
2. `换一首。`
3. `我想听新闻。`
4. `换成戏曲。`
5. `不听了。`

任意阶段说 `不听了。` 都可提前结束。第一首音乐阶段说 `换成新闻`，或任何阶段说 `放段京剧`，应保持静默并且不改变状态。

## 3. 社交活动协助

普通版入口：`scenarios/social_activity_support/run_g1_demo.sh`。

| 顺序 | 测试语句 | 预期结果 |
| --- | --- | --- |
| 1 | `今天有什么活动？` | 查询并推荐活动。 |
| 2 | `第一个。` 或 `唱歌那个。` | 选择当前活动。 |
| 3 | `几点开始？` | 播报时间。 |
| 4 | `在哪儿？` | 播报地点。 |
| 5 | `还有名额吗？` | 播报名额。 |
| 6 | `需要报名吗？` | 播报报名规则。 |
| 7 | `手工那个。` → `我想参加。` → `对。` | 选择需报名活动、确认登记意愿；确认阶段应显示确认灯效。 |
| 8 | `算了。` 或 `不用了。` | 取消当前报名或结束推荐。 |

比赛展示版入口：`scenarios/social_activity_support/run_g1_showcase.sh`。为不占用机器人，先可运行离线状态机：

```bash
python3 scenarios/social_activity_support/text_showcase_demo.py --demo-data --no-llm --scripted
```

比赛版建议链：`明天下午有什么活动？` → `唱歌那个。` → `几点开始？` → `在哪儿？` → `有人数限制吗？` → `需要报名吗？` → `那我去参加。` → `先这样吧。`。报名链则用 `手工那个。` → `我想参加。` → `好的。`。流程外的 `这个活动听起来挺不错的。` 应静默忽略。

## 4. 联系家人

入口：`scenarios/contact_family/run_g1_demo.sh`。测试时保持默认 `--call-backend safe_stub`，不要传 `--call-backend real`。

| 顺序 | 测试语句 | 预期结果 |
| --- | --- | --- |
| 1 | `我想和女儿说说话。` | 匹配授权联系人并请求二次确认。 |
| 2 | `对。` | 确认联系人，进入准备阶段。 |
| 3 | `确认拨号。` | 仅在最终授权阶段有效；safe_stub 会验证流程但绝不真实外拨。 |
| 取消链 | 第 2 步说 `算了。` 或 `不用了。` | 取消，不拨号。 |
| 补充链 | `我想打电话。` → `女儿。` → `对。` → `取消。` | 测试补充联系人和最终取消。 |
| 未匹配 | `我想联系表姐。` | 未找到授权联系人。 |
| 反例 | `今天天气不错。` | 不进入联系家人场景。 |
| 严格授权 | 最终阶段说 `好的。`、`对。`、`确认。` | 均不能授权；必须完整说 `确认拨号。`。 |

离线检查不访问电话后端：

```bash
PYTHONPATH=speech python3 speech/test_contact_family_dial_authorization.py
```

## 开启头灯的主机彩排示例

机器人主机恢复后，在项目的 `speech` 目录运行原有启动命令并追加参数即可。例如：

```bash
bash scenarios/care_consultation_support/run_g1_demo.sh \
  --robot-leds execute --confirm-g1-led-demo
```

需要同时启用已接入的手势时，再追加 `--robot-actions execute --confirm-g1-actions`。先用默认参数完整走一次语音流程，确认日志中的“灯光请求”和“动作请求”与场景边界一致后，再加执行参数。实际灯光和手势分别由已有脚本/执行器负责，本仓库的 speech 代码不直接调用机器人 SDK。
